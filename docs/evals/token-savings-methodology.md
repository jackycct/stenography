# Token-Savings Methodology

## Purpose

Define how Stenography proves token savings without losing critical task context.

Performance claims are measured only when backed by AgentLens artifacts. Without AgentLens output, numbers are targets or hypotheses.

## Benchmark Variants

Each benchmark task must run at least two comparable variants against the same issue, commit, agent model, tool permissions, and validation commands.

| Variant | Input | Purpose |
| --- | --- | --- |
| `baseline_raw` | issue text + manually selected repo excerpts | Represents common ad hoc agent context. |
| `baseline_analysis` | issue text + external analysis JSON, uncompressed | Measures Stenography packing vs repo-understanding output alone. |
| `stenography_enabled` | issue text + Stenography Markdown pack + pack JSON metadata | Measures deterministic context packing. |

Optional variants may compare verbose hand-written context, repo wiki only, or alternate token budgets. Do not compare unrelated tasks as evidence for token savings.

## Benchmark Tracks

| Track | Task Shape | Required Evidence |
| --- | --- | --- |
| workflow golden task | Real workflow issue flow with and without Stenography packs | AgentLens run pair + validation command output. |
| SWE-bench-style issue fixing | Public repo issue using raw context vs Stenography pack | Patch result + test pass/fail + missing-context classification. |
| ProgramBench small tasks | Behavior reconstruction in small repos such as `gron`, `tokei`, or `csview` | Output equivalence or tests + token/cost deltas. |

## Metrics

| Metric | Definition | Owner |
| --- | --- | --- |
| input context tokens | Tokens sent to the coding agent before task execution, excluding generated assistant output. | AgentLens |
| output context tokens | Tokens generated by the coding agent during the task. | AgentLens |
| estimated tokens | Deterministic local estimate from Stenography metadata, currently `ceil(chars / 4)`. | Stenography |
| actual model tokens | Provider-reported prompt/completion tokens where available. | AgentLens |
| token savings | `(baseline_total_tokens - stenography_total_tokens) / baseline_total_tokens`. | AgentLens |
| missing-context failure rate | Missing-context failures divided by attempted tasks. | reviewer + AgentLens |
| task success rate | Successful tasks divided by attempted tasks, based on acceptance criteria. | reviewer + CI |
| test pass rate | Passing validation/test commands divided by commands run, when tests exist. | CI + AgentLens |
| tool-call count change | `stenography_tool_calls - baseline_tool_calls`. | AgentLens |
| elapsed-time change | `stenography_elapsed - baseline_elapsed`. | AgentLens |
| cost per successful run | Total run cost divided by successful completions. | AgentLens |

## Missing-Context Failure

A compression fails due to missing context when all conditions hold:

1. The task fails acceptance criteria or validation.
2. The omitted fact, file, symbol, command, constraint, or architectural boundary was present in the baseline input or discoverable from allowed source inputs.
3. A reasonable agent using the omitted context could have avoided the failure without unrelated new information.
4. The failure is not better explained by implementation error, flaky tooling, dependency outage, model refusal, auth failure, or an ambiguous issue.

Classify failures with one primary reason:

| Reason | Meaning |
| --- | --- |
| `missing_required_file` | Pack omitted a file needed to understand or edit behavior. |
| `missing_symbol_or_api` | Pack omitted a function, class, CLI arg, schema field, or public contract. |
| `missing_constraint` | Pack omitted an acceptance criterion, boundary, safety rule, or non-goal. |
| `misleading_context` | Pack included stale or incorrect context that caused the failed change. |
| `not_context_related` | Failure came from implementation, env, auth, flaky tests, or unclear task scope. |

## Procedure

1. Select a task with stable acceptance criteria.
2. Pin repo commit SHA, agent model, tool policy, token budget, and validation commands.
3. Generate baseline inputs and Stenography-enabled inputs from the same source materials.
4. Run equivalent coding-agent attempts with AgentLens collection enabled.
5. Record patch outcome, validation output, review result, and failure classification.
6. Compare paired runs within the same task and report aggregate results only after task-level records are available.
7. Attach AgentLens artifact links before publishing measured claims.

## AgentLens Collection

AgentLens owns telemetry capture and reporting. Stenography must not own dashboards, run scheduling, or A/B orchestration.

AgentLens should capture these fields per run:

```json
{
  "task_id": "issue-123",
  "track": "swe_bench_style",
  "variant": "stenography_enabled",
  "repo": "owner/name",
  "commit": "0123456789abcdef",
  "agent_model": "model-name",
  "token_budget": 30000,
  "pack_json": ".stenography/packs/issue-123.pack.json",
  "input_context_tokens": 12000,
  "output_context_tokens": 18000,
  "actual_prompt_tokens": 12150,
  "actual_completion_tokens": 17920,
  "tool_calls": 42,
  "elapsed_seconds": 900,
  "estimated_cost_usd": 1.25,
  "validation_commands": ["npm test"],
  "validation_result": "pass",
  "task_result": "success",
  "failure_reason": null,
  "artifact_url": "https://agentlens.example/runs/issue-123"
}
```

Reports should include:

- one row per run
- paired baseline/Stenography deltas by task
- aggregate token savings only across comparable task pairs
- missing-context failure rate by track and failure reason
- links to raw AgentLens artifacts for every measured claim

## Reporting Rules

- Use "target" or "hypothesis" for unmeasured numbers.
- Use "measured" only with an AgentLens artifact link.
- Include baseline type, task id, commit SHA, and validation command.
- Report failed Stenography runs even when token savings are high.
- Do not optimize for maximum compression if task success or test pass rate degrades.

## Claim Threshold

A README or release claim may say "measured" only when:

- every reported task has an AgentLens artifact
- each Stenography run is paired with a baseline run
- missing-context failures are reported beside token savings
- validation commands and outcomes are visible
- the claim identifies the benchmark track and date
